Before - Without Package

Manual Query Building (50+ lines)

public function index(Request $request) { $query = User::query(); // Manual filtering - repetitive! if ($request->has('name')) { $query->where('name', 'like', '%'.$request->name.'%'); } if ($request->has('status')) { $query->where('status', $request->status); } if ($request->has('min_salary')) { $query->where('salary', '>=', $request->min_salary); } if ($request->has('max_salary')) { $query->where('salary', '<=', $request->max_salary); } // Manual sorting - error prone! $sort = $request->get('sort', 'created_at'); $direction = strpos($sort, '-') === 0 ? 'desc' : 'asc'; $sort = ltrim($sort, '-'); $query->orderBy($sort, $direction); // Manual pagination $perPage = $request->get('per_page', 15); return $query->paginate($perPage); }
After - With Package

Clean & Concise (10 lines)

public function index(Request $request) { return QueryBuilder::for(User::class, $request) ->allowedFilters([ 'name', 'status', AllowedFilter::gte('salary'), AllowedFilter::lte('salary'), ]) ->allowedSorts(['name', 'created_at']) ->searchable(['name', 'email']) ->paginate(); }

Same functionality, 80% less code, 100% secure!

Get Started in 5 Minutes

Three simple steps to transform your API

Install Package

Run composer require and publish the config

composer require magetech/laravel-query-toolkit php artisan mts:query:install
2

Configure Query

Define your allowed filters, sorts, and includes

->allowedFilters(['name', 'status']) ->allowedSorts(['name', 'created_at']) ->searchable(['name', 'email'])

Return Results

Use paginate() or get() to return data

return QueryBuilder::for(User::class) ->allowedFilters([...]) ->paginate();

Frequently Asked Questions

Everything you need to know

How long does it take to set up?
Less than 5 minutes! Just run composer require, publish the config, and start using the QueryBuilder in your controllers.
Does it work with existing Laravel projects?
Yes! The package is designed to work alongside your existing code. You can adopt it incrementally, one controller at a time.
Is it secure?
Absolutely. The whitelist-only security model ensures only explicitly allowed filters can be executed. All queries use parameterized statements to prevent SQL injection.
Can I customize the query parameters?
Yes! You can customize all URL parameter names (filter, sort, include, fields, search) in the config file to match your API conventions.
Does it support MongoDB or other databases?
Currently, the package supports MySQL, PostgreSQL, and SQLite. MongoDB support may be added in future versions.
What about performance?
The package is optimized for performance. It prevents N+1 queries through eager loading, supports cursor pagination for large datasets, and includes configurable caching for filter metadata.
Can I create custom filter types?
Yes! Use the artisan command php artisan mts:query:make-filter to generate a custom filter class. You can also use callback filters for quick custom logic.
Is there documentation?
Yes! We provide comprehensive documentation including technical architecture docs, this customer guide, and a complete API reference.
