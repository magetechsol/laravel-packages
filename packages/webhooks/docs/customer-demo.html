Architecture

The Webhook Pipeline

Every inbound webhook passes through 7 stages. Each stage is a dedicated, testable class.

Step 1
Receive
HTTP POST arrives
Step 2
Authenticate
HMAC + Timestamp + IP
Step 3
Validate
JSON structure check
Step 4
Persist
Store to database
Step 5
Deduplicate
Idempotency check
Step 6
Process
Invoke handler class
Step 7
Complete
Mark done / retry / dead

If processing fails at Step 6, the webhook enters the retry flow with exponential backoff, then moves to dead-letter queue after exhausting attempts.

HMAC Signature Verification

Database-level unique index on idempotency keys prevents duplicate processing. Works with Stripe event IDs, Shopify webhook IDs, Razorpay entity IDs, and custom keys.

Smart Retry Engine

Exponential backoff with configurable base delay, multiplier, and max delay. Random jitter prevents thundering herd. Failed webhooks are automatically retried up to 5 times.

Outbound Webhooks

Send signed, queued webhooks from your Laravel app. Fluent builder API with signWith(), queue(), and full delivery tracking in the database.

Timestamp validation rejects stale webhooks outside the tolerance window. IP allowlisting adds an extra layer of security for sensitive payment integrations.

📤 Outbound Webhooks

Send a Webhook
use Webhook; // Queued delivery (recommended) Webhook::send('order.created') ->to('https://partner.com/hook') ->payload($order) ->signWith($secret) ->maxAttempts(3) ->queue(); // Synchronous delivery Webhook::send('payment.completed') ->to('https://api.example.com/hook') ->payload($payment) ->signWith($secret) ->now();

Automatic Signing & Tracking

When you call signWith(), three headers are added:

  • X-Webhook-Signature — HMAC-SHA256 of the payload
  • X-Webhook-Timestamp — Unix timestamp
  • X-Webhook-Signed-Payload — SHA256 hash of payload

Every delivery creates a database record tracking status, attempts, response codes, and errors.

FAQ

Frequently Asked Questions

Does this work with Stripe webhooks?
Yes. The package includes built-in Stripe provider support with proper signature verification using Stripe's timestamped HMAC format. Just add your STRIPE_WEBHOOK_SECRET to .env.
Can I add custom webhook providers?
Absolutely. Implement the WebhookProviderContract interface, define your signature header, event extraction, and idempotency key logic. The GenericProvider also works out of the box for any HMAC-SHA256 service.
What happens when a webhook fails?
Failed webhooks are automatically retried with exponential backoff (60s, 120s, 240s, 480s, 960s by default). After exhausting all retry attempts, they're moved to a dead-letter queue where you can inspect, replay, or alert on them.
Is it suitable for production use?
Yes. This package is designed for enterprise production environments with full test coverage (23 test cases), database-level idempotency, queue-based processing, soft deletes, and comprehensive error handling.
Can I send outbound webhooks too?
Yes. The package supports both inbound and outbound webhooks. Use the fluent Webhook facade to send signed, queued webhooks to any URL with full delivery tracking, retry support, and response code recording.
How does deduplication work?
Each provider extracts an idempotency key (Stripe event ID, Shopify webhook ID, etc.). This key is stored with a UNIQUE database index. If the same key arrives again, the duplicate is rejected and returns a 200 OK response (idempotent).
Can I replay failed webhooks?
Yes. Use php artisan mts:webhook:replay {id} to replay a single webhook, or --provider=stripe --from=2026-01-01 to batch-replay. Use --dry-run to preview without processing.
What sensitive data is masked?
By default: password, token, authorization, secret, card_number, cvv, ssn, api_key, and private_key. You can add custom fields in the config. Headers like authorization, cookie, and x-api-key are also redacted.
Does it support Laravel queues?
Yes. Both inbound processing and outbound delivery use Laravel's queue system. Configure queue names, connections, and timeouts per-direction in the config file.
How do I monitor webhook health?
Run php artisan mts:webhook:stats --days=30 for success rates, provider breakdowns, and top events. Listen to WebhookDeadLettered events for real-time alerting. Check --json output for programmatic access.
