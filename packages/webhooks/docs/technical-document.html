MTS Laravel Webhook Manager

Enterprise-grade inbound and outbound webhook infrastructure for Laravel. Provides a complete pipeline for receiving, authenticating, validating, persisting, deduplicating, processing, retrying, and managing webhooks from any provider.

PHP 8.3+ Laravel 13.x v1.0.0 Enterprise

1. Introduction

The MTS Laravel Webhook Manager (magetech/laravel-webhooks) is a complete webhook infrastructure package for Laravel applications. It handles both inbound webhooks (receiving events from external providers like Stripe, Razorpay, Shopify, Magento) and outbound webhooks (sending events from your Laravel application to external URLs).

What Problem Does It Solve?

Webhooks are the backbone of modern integrations, but handling them correctly is deceptively complex. You need signature verification, replay protection, idempotency, retry logic, audit trails, and more. Without a proper framework, teams end up with fragile, ad-hoc webhook handlers scattered across their codebase.

This package provides a single, standardized pipeline that handles every aspect of webhook management with enterprise-grade reliability.

Key Capabilities

  • Inbound Pipeline — Receive, authenticate, validate, persist, deduplicate, process, retry, and dead-letter webhooks
  • Outbound Pipeline — Send signed, queued webhooks with full delivery tracking and retry support
  • Provider Support — Built-in support for Stripe, Razorpay, Shopify, Magento, and a generic provider for any HMAC-SHA256 service
  • Security — HMAC-SHA256 signature verification, timestamp-based replay protection, IP restrictions, and sensitive data masking
  • Reliability — Exponential backoff retry, dead-letter queue, webhook replay, and full audit trail
  • Observability — Statistics commands, lifecycle events, attempt history, and error tracking

Pipeline Source Code

// src/Inbound/Pipeline/WebhookPipeline.php

class WebhookPipeline
{
    public function __construct(
        private readonly Authenticator $authenticator,
        private readonly Validator $validator,
        private readonly Persister $persister,
        private readonly Deduplicator $deduplicator,
        private readonly Processor $processor,
        private readonly Retrier $retrier,
    ) {}

    public function handle(Request $request, string $provider): Webhook
    {
        $startTime = microtime(true);

        // Step 1: Authenticate (HMAC + timestamp + IP)
        $providerInstance = $this->authenticator->authenticate($request, $provider);

        // Step 2: Validate payload structure
        $payload = $this->validator->validate($request, $provider);

        // Step 3: Extract metadata from provider
        $eventName = $providerInstance->extractEventName($request);
        $idempotencyKey = $providerInstance->extractIdempotencyKey($request, $payload);

        // Step 4: Persist to database
        $webhook = $this->persister->persist(/* ... */);

        // Step 5: Dispatch WebhookReceived event
        Event::dispatch(new WebhookReceived($webhook));

        // Step 6: Check for duplicates
        $this->deduplicator->ensureUnique($webhook);

        // Step 7: Process handler
        try {
            $webhook->markAsProcessing();
            $this->processor->process($webhook);
            $webhook->markAsProcessed();
            Event::dispatch(new WebhookProcessed($webhook));
        } catch (\Throwable $exception) {
            Event::dispatch(new WebhookFailed($webhook, $exception));
            $this->retrier->handle($webhook, $exception);
        }

        return $webhook;
    }
}

6. Authentication

The Authenticator class resolves the correct provider implementation and runs three security checks:

// src/Inbound/Pipeline/Authenticator.php

class Authenticator
{
    private const PROVIDER_MAP = [
        'stripe'   => StripeProvider::class,
        'razorpay' => RazorpayProvider::class,
        'shopify'  => ShopifyProvider::class,
        'magento'  => MagentoProvider::class,
        'generic'  => GenericProvider::class,
    ];

    public function authenticate(Request $request, string $provider): WebhookProviderContract
    {
        $providerInstance = $this->resolveProvider($provider);

        // Check 1: HMAC signature verification
        if (config('mts-webhooks.security.verify_hmac', true)) {
            $this->verifySignature($request, $providerInstance);
        }

        // Check 2: Timestamp validation (replay protection)
        if (config('mts-webhooks.security.verify_timestamp', true)) {
            $this->verifyTimestamp($request, $providerInstance);
        }

        // Check 3: IP restrictions
        $this->verifyIpRestrictions($request);

        return $providerInstance;
    }
}

7. Signature Verification

Each provider implements its own signature verification strategy via the WebhookProviderContract interface.

Provider Contract

// src/Contracts/WebhookProviderContract.php

interface WebhookProviderContract
{
    public function name(): string;
    public function verifySignature(Request $request, string $secret): bool;
    public function extractEventName(Request $request): ?string;
    public function extractIdempotencyKey(Request $request, array $payload): ?string;
    public function getSignatureHeader(): string;
    public function getTimestampFromRequest(Request $request): ?int;
}

Generic HMAC-SHA256 Verification

// Abstract base class (used by Razorpay, Magento, Generic)
protected function computeSignature(string $payload, string $secret): string
{
    return hash_hmac('sha256', $payload, $secret);
}

public function verifySignature(Request $request, string $secret): bool
{
    $signature = $request->header($this->getSignatureHeader());
    $payload = $request->getContent();
    $expected = $this->computeSignature($payload, $secret);
    return hash_equals($expected, $signature);
}

Stripe Timestamped Signature

Stripe uses a unique format with t=timestamp,v1=signature:

// src/Inbound/Providers/StripeProvider.php
public function verifySignature(Request $request, string $secret): bool
{
    $signatureHeader = $request->header('Stripe-Signature');
    $signatureParts = $this->parseSignatureHeader($signatureHeader);
    // Stripe signs: timestamp + "." + payload
    $signedPayload = $signatureParts['timestamp'] . '.' . $payload;
    $expected = hash_hmac('sha256', $signedPayload, $secret);
    return hash_equals($expected, $signatureParts['signature']);
}

Shopify Base64 HMAC

Shopify uses base64-encoded HMAC-SHA256:

// src/Inbound/Providers/ShopifyProvider.php
public function verifySignature(Request $request, string $secret): bool
{
    $payload = $request->getContent();
    $computed = base64_encode(hash_hmac('sha256', $payload, $secret, true));
    return hash_equals($computed, $signature);
}

8. Timestamp Validation

Protects against replay attacks by rejecting webhooks with timestamps outside the configured tolerance window.

// src/Inbound/Pipeline/Authenticator.php
private function verifyTimestamp(Request $request, WebhookProviderContract $provider): void
{
    $timestamp = $provider->getTimestampFromRequest($request);
    if ($timestamp === null) return;

    $tolerance = config('mts-webhooks.security.timestamp_tolerance', 300);
    $diff = abs(time() - $timestamp);

    if ($diff > $tolerance) {
        throw new ReplayAttackException(
            'Webhook timestamp is outside the allowed tolerance window. '
            . 'Diff: ' . $diff . 's, Tolerance: ' . $tolerance . 's'
        );
    }
}
Configuration

Set MTS_WEBHOOKS_TIMESTAMP_TOLERANCE in your .env file. Default is 300 seconds (5 minutes). Set to 0 to disable timestamp validation.

10. Idempotency & Deduplication

Prevents duplicate webhook processing via a database-level unique index on idempotency_key.

How It Works

  1. Each webhook receives an idempotency_key from the provider (event ID, entity ID, or custom header)
  2. The key is stored with a UNIQUE index in the mts_webhooks table
  3. Before processing, the Deduplicator checks for existing records with the same key
  4. If a duplicate is found, a DuplicateWebhookException is thrown and the webhook returns 200 OK (idempotent response)

Idempotency Key Sources by Provider

ProviderKey SourceExample

Razorpaypayload.payload.payment.entity.idpay_1234567890
ShopifyX-Shopify-Webhook-Id headerabc123...
MagentoX-Magento-Webhook-Id headerwebhook_123
GenericX-Webhook-Id header or payload.idAny unique string

Deduplicator Source

// src/Inbound/Pipeline/Deduplicator.php
public function ensureUnique(Webhook $webhook): void
{
    $idempotencyKey = $webhook->idempotency_key;
    if ($idempotencyKey === null) return;

    DB::transaction(function () use ($idempotencyKey, $webhook) {
        $existing = Webhook::where('idempotency_key', $idempotencyKey)
            ->where('id', '!=', $webhook->id)
            ->lockForUpdate()
            ->first();

        if ($existing !== null) {
            throw new DuplicateWebhookException(
                'Duplicate webhook detected with idempotency key: ' . $idempotencyKey
            );
        }
    });
}

namespace App\Handlers;

use MageTech\Webhooks\Contracts\WebhookHandlerContract;

class PaymentSucceeded implements WebhookHandlerContract
{

        $paymentId = $payload['id'];
        $amount = $payload['amount'];

        // Update order status
        Order::where('payment_id', $paymentId)->update([

Handler Resolution

The Processor first checks for provider.event in the handler map. If not found, it checks for just event. If no handler is registered, the webhook is marked as processed (no-op).

12. Retry Mechanism

Failed webhooks are automatically retried using exponential backoff with jitter.

Retry Formula

delay = min(baseDelay × multiplier^attempt, maxDelay) + jitter

Where:
  baseDelay          = 60 seconds (configurable)
  multiplier         = 2 (configurable)
  maxDelay           = 3600 seconds (configurable)
  jitter             = random(±10%)

Retry Schedule Example

AttemptBase DelayWith BackoffCumulative Wait
160s~60s1 min
260s~120s3 min
360s~240s7 min
460s~480s15 min
560s~960s31 min

Retry Configuration

    'max_attempts'        => env('MTS_WEBHOOKS_MAX_ATTEMPTS', 5),
    'base_delay'          => env('MTS_WEBHOOKS_BASE_DELAY', 60),
    'max_delay'           => env('MTS_WEBHOOKS_MAX_DELAY', 3600),
    'backoff_multiplier'  => env('MTS_WEBHOOKS_BACKOFF_MULTIPLIER', 2),
    'retryable_exceptions' => [],
],

Retry Strategy Source

// src/Support/RetryStrategy.php
public function calculateNextRetry(
    int $attempt,
    int $baseDelay = 60,
    int $maxDelay = 3600,
    float $multiplier = 2.0,
): Carbon {
    $delay = $baseDelay * pow($multiplier, $attempt - 1);
    $delay = min($delay, $maxDelay);
    $jitter = $delay * (mt_rand(-10, 10) / 100);
    $delay = max(1, $delay + $jitter);
    return Carbon::now()->addSeconds((int) $delay);
}

13. Dead Letter Queue

When all retry attempts are exhausted, the webhook is moved to dead letter status. This is a terminal state that preserves the webhook for investigation.

Dead Letter Flow

// src/Inbound/Pipeline/DeadLetterHandler.php
public function handle(Webhook $webhook, \Throwable $exception): void
{
    $webhook->markAsDead($exception->getMessage());

    app(Persister::class)->recordAttempt(
        webhook: $webhook,
        attemptNumber: $webhook->attempts,
        status: 'failed',
        error: 'Dead letter: ' . $exception->getMessage(),
    );

    // Dispatch Laravel event for monitoring
    Event::dispatch(new WebhookDeadLettered($webhook));

    // Dispatch custom event if configured
    $customEventClass = config('mts-webhooks.dead_letter.event');
    if ($customEventClass !== null) {
        Event::dispatch(new $customEventClass($webhook));
    }
}

Monitoring Dead Letters

use MageTech\Webhooks\Events\WebhookDeadLettered;

// In EventServiceProvider or a listener
Event::listen(WebhookDeadLettered::class, function (WebhookDeadLettered $event) {
    $webhook = $event->webhook;

    // Send alert to Slack, email, or monitoring system
    Alert::webhookFailed($webhook->provider, $webhook->event, $webhook->error);

    // Log to error tracking service
    Log::error('Webhook dead letter', [
        'id'         => $webhook->id,
        'provider'   => $webhook->provider,
        'event'      => $webhook->event,
        'attempts'   => $webhook->attempts,
        'error'      => $webhook->error,
    ]);
});

14. Sensitive Data Masking

All webhook payloads are automatically masked before database storage. Sensitive fields are configured in the config file.

Default Masked Fields

        'card_number',
        'cvv',
        'ssn',
        'api_key',
        'private_key',

Masking Behavior

// src/Support/SensitiveDataMasker.php
private function maskValue(string $value): string
{
    $length = strlen($value);
    if ($length <= 4) return str_repeat('*', $length);

    $visibleChars = min(4, (int) ceil($length * 0.2));
    $maskedPart = str_repeat('*', $length - $visibleChars);
    return substr($value, 0, $visibleChars) . $maskedPart;
}

// Example:
// "secret123"        → "secr*******"
// "abc-def-ghi-jkl"  → "abc-********"
// "4111111111111111"  → "4111**************"
// "ab"               → "**"
Headers Are Also Sanitized

The Persister automatically redacts sensitive HTTP headers: authorization, cookie, set-cookie, x-api-key.

15. Outbound Webhooks

Send webhooks from your Laravel application using a fluent builder API. Supports both synchronous and queued delivery.

Fluent Builder API

use MageTech\Webhooks\Support\Facades\Webhook;

// Synchronous delivery (blocks until delivered)
$delivery = Webhook::send('order.created')
    ->to('https://partner.example.com/webhook')
    ->payload([
        'order_id' => $order->id,
        'total'    => $order->total,
        'status'   => $order->status,
    ])
    ->signWith('my-webhook-secret')
    ->withHeaders(['X-Custom-Header' => 'value'])
    ->maxAttempts(3)
    ->now();

// Queued delivery (non-blocking)
$delivery = Webhook::send('payment.completed')
    ->to('https://api.example.com/payments/webhook')
    ->payload($payment)
    ->signWith($secret)
    ->queue();  // or ->queue('webhooks')

16. Outbound Request Signing

When you call signWith($secret), three headers are added to the outgoing request:

// src/Outbound/Signer.php
public function generateHeader(string $payload, string $secret): array
{
    return [
        'X-Webhook-Signature'     => hash_hmac('sha256', $payload, $secret),
        'X-Webhook-Timestamp'     => (string) time(),
        'X-Webhook-Signed-Payload' => hash('sha256', $payload),

}

Stripe Provider

Stripe uses a timestamped signature format. The Stripe-Signature header contains t=timestamp,v1=signature pairs.

// Stripe sends:
// Stripe-Signature: t=1234567890,v1=5257a869e7ecebeda32affa62cdca3fa51cad7e77a0e56ff536d0ce8e108d8bd

Razorpay Provider

Razorpay uses standard HMAC-SHA256 over the raw request body.

# .env
RAZORPAY_WEBHOOK_SECRET=your_razorpay_secret

Shopify Provider

Shopify uses base64-encoded HMAC-SHA256 and sends the event topic in the X-Shopify-Topic header (e.g., orders/create).

# .env
SHOPIFY_WEBHOOK_SECRET=your_shopify_secret

Magento Provider

Magento uses HMAC-SHA256 with event and webhook ID in custom headers.

# .env
MAGENTO_WEBHOOK_SECRET=your_magento_secret

Custom / Generic Provider

For any provider not listed above. Uses X-Webhook-Signature, X-Webhook-Event, and X-Webhook-Id headers.

namespace App\Webhooks\Providers;

use MageTech\Webhooks\Inbound\Providers\AbstractProvider;

class SalesforceProvider extends AbstractProvider
{
    public function name(): string
    {
        return 'salesforce';
    }

    public function getSignatureHeader(): string
    {
        return 'X-Salesforce-Signature';
    }

    public function extractEventName(Request $request): ?string
    {
        return $request->header('X-Salesforce-Event');
    }

    public function extractIdempotencyKey(Request $request, array $payload): ?string
    {
        return $payload['event_id'] ?? $request->header('X-Salesforce-Event-Id');
    }
}

Listening to Events

use MageTech\Webhooks\Events\WebhookProcessed;
use MageTech\Webhooks\Events\WebhookDeadLettered;

// In EventServiceProvider $listen array
protected $listen = [
    WebhookProcessed::class => [
        App\Listeners\LogWebhookProcessed::class,
    ],
    WebhookDeadLettered::class => [
        App\Listeners\AlertDeadLetter::class,

Event::listen(WebhookProcessed::class, function ($event) {

});
